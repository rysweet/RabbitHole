# Legacy Fixture Round-Trip Readiness

Legacy fixture round-trip readiness is the focused compatibility lane for
generated Alice archive fixtures in `core/story-api-migration` and the desktop
QA smoke that exposes that lane to reviewers.

The lane proves that selected legacy-shaped project, player, and type fixtures
can be written, inspected, read through the production `IoUtilities` boundary,
and written/read again where round-trip behavior is in scope. It also proves a
small allowlist of JSON `.a3w` and `.a3c` decode boundaries. Unsupported archive
shapes fail at the archive I/O boundary with explicit checked failures.

## Scope

This feature covers targeted fixture behavior only:

| Fixture shape | Proven behavior |
| --- | --- |
| Generated editable `.a3p` project fixture | XML fallback archive entries, manifest metadata, resource bytes, `ResourceExpression` rebinding, and write/read/write/read preservation. |
| Generated `.a3w` player fixture with simple supported Tweedle | JSON manifest routing, Tweedle source entry presence, program type decode, scene-camera metadata preservation, and export/read/export/read preservation. |
| Generated JSON `.a3w` player boundary fixtures | Manifest-declared program and sibling type decode for the documented narrow shapes: scene fields, image resources, null field initializers, primitive-return methods, unnamed sibling type recovery with a primitive-return method, same-type zero-argument `this.method()` calls, simple `if` bodies, empty constructors, field-return methods, and literal arithmetic field initializers. |
| Generated `.a3c` type fixture | XML fallback archive entries, resource bytes, `ResourceExpression` rebinding, and write/read/write/read preservation. |
| Generated JSON `.a3c` type boundary fixtures | Manifest-declared type decode for the documented narrow shapes: field-only resource readback, primitive-return methods, empty constructors, constructor field assignment, and null text-field initializers. |
| Explicit unsupported fixtures | Checked `IOException` or `VersionNotSupportedException` at `IoUtilities` rather than silent fallback or partial success. |

The fixtures are generated by tests in a temporary folder. They are not checked
in binary archives, Git LFS objects, real user projects, or full historical
corpus payloads.

## Usage

Use this lane when reviewing changes to Alice archive I/O that could affect:

- `IoUtilities` reader selection;
- `.a3p`, `.a3w`, or `.a3c` archive entry names;
- `manifest.json` metadata used by generated fixtures;
- XML fallback routing for editable project and type fixtures;
- JSON player archive routing for simple generated player fixtures;
- the documented JSON `.a3w` and `.a3c` decode boundary allowlist;
- image resource serialization and readback;
- fail-closed handling for unsupported fixture shapes.

The executable characterization lives in:

```text
core/story-api-migration/src/test/java/org/lgna/project/io/HistoricalArchiveRoundTripCharacterizationTest.java
```

The focused suite should stay synthetic and deterministic. Add fixtures by
building small in-memory Alice project objects or tiny generated zip entries,
then read them through the public production API.

## Archive contracts

### Editable project `.a3p`

The generated editable project fixture is written with
`IoUtilities.writeProject(File, Project, DataSource...)`.

The archive contains:

```text
version.txt
manifest.json
programType.xml
resources.xml
resources/historical-project-texture.png
```

It does not contain:

```text
src/GeneratedHistoricalProject.twe
```

That absence is part of the contract. The editable project fixture exercises XML
fallback behavior even though the archive contains `manifest.json`.

Readback through `IoUtilities.readProject(File)` preserves the program type
name, `SProgram` supertype, scene-camera type, image resource identity, original
file name, content type, resource bytes, and AST resource-expression binding.

The read project is written again to a second `.a3p` archive and must preserve
the same observable contract.

### Player `.a3w`

The generated player fixture is written with
`IoUtilities.exportProject(File, Project, DataSource...)`.

The simple supported fixture contains:

```text
version.txt
manifest.json
src/GeneratedHistoricalProgram.twe
```

The manifest declares `metadata.fileType` as `a3w`, names the generated program
type, preserves scene-camera metadata, and points at the Tweedle source entry.

Readback through `IoUtilities.readProject(File)` decodes the simple generated
program type and preserves scene-camera metadata. The read project is exported
again to a second `.a3w` archive and must preserve the same supported simple
player contract.

Unsupported player fixtures are separate from this supported slice. If a
manifest-declared source entry is missing, a parent type is unresolved, or the
Tweedle source reaches an unsupported decoder boundary, the reader fails with
`IOException` unless the test explicitly documents a narrower legacy
compatibility recovery case.

The JSON player fixture allowlist is intentionally narrow. It covers generated
manifest-declared program and sibling type sources that use:

- fields typed by decoded sibling scene types;
- manifest-backed image resources;
- `null` field initializers;
- primitive-return methods;
- unnamed sibling types with primitive-return methods;
- methods returning `this.<field>`;
- empty constructors;
- literal arithmetic field initializers on non-resource fields;
- simple `if` bodies with supported condition and body shapes;
- zero-argument same-type `this.method()` calls.

Neighboring unsupported shapes must fail closed instead of returning partial
programs. The fail-closed set includes mixed identifiers in unsupported
initializers, unresolved parent types, missing manifest-declared source entries,
argument-bearing explicit `this.method(label: value, ...)` calls, and resource
field initializers that require unsupported archive binding context.

### Type `.a3c`

The generated type fixture is written with
`IoUtilities.writeType(File, NamedUserType, DataSource...)`.

The archive contains:

```text
version.txt
type.xml
resources.xml
resources/historical-type-texture.png
```

It does not contain:

```text
manifest.json
```

Readback through `IoUtilities.readType(File)` preserves the user type, the
associated resource collection, resource bytes, and resource-expression binding.
The read type is written again to a second `.a3c` archive and must preserve the
same observable contract.

Generated JSON `.a3c` type fixtures are also characterized at the public
`IoUtilities.readType(File)` boundary. The supported JSON type slice covers:

- field-only Tweedle with manifest-backed image resource readback;
- primitive-return methods;
- empty constructors;
- constructor body assignment from `this.<field> <- <literal>`;
- `null` text-field initializers.

Unsupported JSON type fixtures fail closed for complex initializers and
unresolved parent types. These failures are archive-boundary diagnostics, not
evidence that arbitrary JSON type archives are migratable.

### Unsupported fixture shapes

Unsupported shapes fail closed. Tests should assert the checked failure and the
stable diagnostic context, not a null program type or silent data loss.

Examples of unsupported shapes include:

- XML project archives below the supported migration floor;
- JSON player archives whose manifest-declared source entry is missing;
- JSON player archives whose program or sibling parent type cannot be resolved;
- JSON player archives whose Tweedle source reaches an unsupported decoder
  boundary.

Corrupt manifest and manifest/file-type mismatch routing belongs to the broader
`IoUtilities` test surface unless a fixture is added to
`HistoricalArchiveRoundTripCharacterizationTest`.

## API reference

The lane uses existing production APIs only:

```java
Project project = IoUtilities.readProject(projectArchive);
IoUtilities.writeProject(projectArchive, project);
IoUtilities.exportProject(playerArchive, project);

TypeResourcesPair pair = IoUtilities.readType(typeArchive);
IoUtilities.writeType(typeArchive, pair.getType());
```

`IoUtilities.readProject` and `IoUtilities.readType` are the public archive
boundaries. They may throw `IOException` or `VersionNotSupportedException` for
unsupported fixture shapes.

Tests should not bypass reader selection by directly constructing lower-level
readers unless the test is explicitly about that lower-level boundary.

Reader routing remains:

| Archive state | Reader behavior |
| --- | --- |
| `.a3p` generated project with readable `manifest.json` | XML fallback reader. |
| `.a3w` generated player with readable `manifest.json` | JSON player reader. |
| `.a3c` XML fallback type fixture without `manifest.json` | XML type reader. |
| JSON player or type fixture with a readable manifest but an unsupported generated source shape | Checked failure at the public archive boundary. |

## Configuration

There is no runtime Alice setting for this feature. It uses the repository's
existing Maven, JUnit 4, and temporary-folder test setup.

Initialize the Tweedle grammar submodule in fresh checkouts or worktrees before
Maven validation:

```bash
git submodule update --init tweedle-lang
test -d tweedle-lang/Grammar
```

Automation can keep the saved Node memory setting:

```bash
export NODE_OPTIONS=--max-old-space-size=32768
```

`NODE_OPTIONS` is not an archive I/O feature flag.

## Validation

Run the focused readiness suite from the repository root:

```bash
NODE_OPTIONS=--max-old-space-size=32768 \
mvn -DincludeSims=false -Dinstall4j.skip \
  -DfailIfNoTests=false \
  -Dsurefire.failIfNoSpecifiedTests=false \
  -pl core/story-api-migration -am \
  -Dtest=org.lgna.project.io.HistoricalArchiveRoundTripCharacterizationTest \
  test
```

The command above is the canonical form for docs and PR evidence. Adding `-q` is
only a Maven log-verbosity choice and does not change the evidence scope.
Run the command directly from the shell or CI job. Do not wrap this focused gate
in an external timeout helper; a timeout result is not fixture-readiness evidence.
This does not conflict with the QA scenario `timeoutSeconds` field. That field is
runner metadata for bounding gated-smoke execution, not a substitute for the
canonical Maven result.

For PR readiness evidence, record the commit SHA that was pushed and the exact
focused command that ran at that SHA. Evidence gathered before the final commit
is not final-head evidence.

## PR evidence wording

PR notes for this lane should name the exact PR head SHA used for final
validation and the integration target used for merge-readiness review. The note
should separate completed evidence from pending checks and avoid green/readiness
claims while checks are pending.

Use this shape:

```text
Legacy fixture round-trip lane evidence for <head-sha> against <base-branch>:

Completed evidence:
- Focused Maven characterization:
  NODE_OPTIONS=--max-old-space-size=32768 mvn -DincludeSims=false -Dinstall4j.skip -DfailIfNoTests=false -Dsurefire.failIfNoSpecifiedTests=false -pl core/story-api-migration -am -Dtest=org.lgna.project.io.HistoricalArchiveRoundTripCharacterizationTest test
- QA/scenario coverage: archive-fixture-smoke is wired through the scenario, validator, runner, schema, and schema contract.
- Docs coverage: reference, how-to, tutorial, and docs index describe the bounded legacy fixture round-trip lane and non-claims.
- Quality-audit cycle: SEEK identified the bounded lane and non-claims; VALIDATE ran the focused evidence; FIX kept changes scoped to generated fixture round-trip readiness.
- Focused-scope review: no broad historical migration, full Tweedle decode, full player decode, arbitrary user archive, or desktop UI behavior claim is included.
- CI: <required checks completed successfully|required checks pending: names>.

Pending checks:
- <check name>: <queued|in_progress|pending>

Non-claims:
- No full historical archive migration claim.
- No full Tweedle decode claim.
- No full player decode claim.
- No arbitrary user archive support claim.
```

If all checks have completed successfully, the PR note may say the named checks
completed successfully. If any check is pending, the note should say the focused
local evidence is complete and CI is pending; it should not say fully ready,
fully green, or all checks passed.

## Merge-ready evidence contract

The lane is merge-ready only when the PR head is up to date with the integration
target, local evidence applies to the final pushed head, and the PR body carries
the same bounded claims as the documentation.

Before using final merge-ready wording, verify the GitHub PR state itself:

| GitHub readiness check | Required result |
| --- | --- |
| Current head | `headRefOid` from GitHub matches local `git rev-parse HEAD`. |
| PR state | The PR is open and not draft. |
| Integration target | The PR base is the intended integration branch. |
| Mergeability | `mergeStateStatus` is `CLEAN` for the current base. |
| Required checks | Required entries in `statusCheckRollup` are `SUCCESS`; any queued, in-progress, pending, failing, cancelled, or skipped required check blocks strict merge-ready wording. |
| Review decision | `reviewDecision` is `APPROVED` before the PR is described as approved. An empty value is not approval. |

When the target branch changes, update the PR branch by merging the current
integration target into it. Do not rebase, force-push, or merge the PR branch
into the target branch manually. Resolve conflicts only in the bounded legacy
fixture round-trip lane before refreshing evidence.

The merge-ready evidence block should include:

| Evidence area | Required wording |
| --- | --- |
| QA/scenario | `archive-fixture-smoke` is explicitly wired through the scenario, runner, validator, schema, and schema contract. |
| Docs | The reference, how-to, tutorial, and docs index describe the implemented lane, usage, validation, and non-claims. |
| Quality audit | The SEEK/VALIDATE/FIX loop names the scoped lane, the focused evidence, and any scoped fixes. |
| CI | Required checks are reported by name as successful, pending, queued, or in progress. |
| Focused validation | The exact no-timeout Maven command and final head SHA are recorded. |
| Focused scope | The note repeats the non-claims for full historical migration, full Tweedle decode, full player decode, arbitrary user archive support, and desktop UI behavior. |

The evidence block should not treat a clean focused review as a substitute for
current-base mergeability. A clean focused current-head review is not
merge-ready evidence after the target branch changes. If the target branch has
changed since that review, update the branch, rerun the focused evidence that
can be affected by the merge, and refresh the PR body before claiming strict
merge-ready status.

## Examples

### Supported `.a3p` round trip

```text
Given a generated project named GeneratedHistoricalProject
And the project references historical-project-texture.png through a ResourceExpression
When IoUtilities.writeProject writes generated-historical-project.a3p
Then the archive contains manifest.json, programType.xml, resources.xml, and the resource bytes
And the archive does not contain src/GeneratedHistoricalProject.twe
When IoUtilities.readProject reads the archive
Then the program type, scene-camera type, resource bytes, and ResourceExpression binding are preserved
When the read project is written and read again
Then the same observable project archive contract is preserved
```

### Supported `.a3w` simple player round trip

```text
Given a generated project named GeneratedHistoricalProgram
When IoUtilities.exportProject writes generated-historical-world.a3w
Then manifest.json names GeneratedHistoricalProgram and points at src/GeneratedHistoricalProgram.twe
When IoUtilities.readProject reads the archive
Then the simple generated program type decodes
When the read project is exported and read again
Then the same simple player archive contract is preserved
```

### JSON boundary fixture

```text
Given a generated JSON .a3w or .a3c fixture whose manifest names one of the documented supported Tweedle shapes
When IoUtilities reads the archive through the public project or type boundary
Then the decoded program or type contains the asserted fields, methods, constructors, resources, or statements for that shape
And neighboring unsupported shapes fail with a checked archive-boundary exception instead of partial decode
```

### Unsupported archive floor

```text
Given a generated XML project archive declaring version 3.0.0.0
When IoUtilities.readProject reads the archive
Then reading throws VersionNotSupportedException
And the exception reports the explicit minimum supported XML decoder version
```

## Claim boundaries

This lane proves only the targeted generated fixture behavior above.

It does not claim:

- full historical archive migration;
- broad compatibility for arbitrary old `.a3p`, `.a3w`, or `.a3c` files;
- full Tweedle language decode;
- full player-to-editor decode;
- runtime player execution;
- desktop UI save/open behavior;
- migration-manager correctness beyond the fixture IO boundary;
- safety for user-provided archives beyond the explicitly tested fail-closed
  archive I/O behavior.

PR notes and review comments should use the same bounded language: focused
legacy fixture round-trip readiness passed at the named final head, with broader
migration and decode support explicitly out of scope.
