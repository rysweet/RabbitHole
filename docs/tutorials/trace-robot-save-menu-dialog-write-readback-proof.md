# Tutorial: Trace the Robot Save Menu Dialog Write/Readback Proof

This tutorial shows how to review the rendered Save proof from scenario execution to canonical evidence generated by `SaveOperationCompletionEvidence`. Legacy timeout-wrapped runs or old `schema_version` artifacts are outside this tutorial.

The examples below are focused excerpts from the artifact contract. Numeric values and `runId` values are run-specific, so use the generated JSON from a test run as evidence.

## Goal

Confirm one Alice desktop Save path:

```text
Robot File -> Save
  -> production Swing Save dialog
  -> controlled chooser approval
  -> .a3p file write
  -> IoUtilities.readProject(...)
  -> robotSaveMenuRoundTripMarker found in the readback project
```

This tutorial does not prove Save As, native file dialogs, every Save variant, lesson completion, grading, or broad desktop automation.

## 1. Run the outside-in scenario

From the repository root:

```bash
git submodule update --init tweedle-lang
export NODE_OPTIONS=--max-old-space-size=32768

NODE_OPTIONS=--max-old-space-size=32768 \
ALICE_QA_RUN_GATED_SMOKES=1 \
qa/outside-in/alice-desktop/runners/run-scenario.sh run \
  alice-desktop-save-menu-dialog-write-proof
```

On a headless host, wrap the scenario in Xvfb:

```bash
xvfb-run -a bash -lc 'NODE_OPTIONS=--max-old-space-size=32768 ALICE_QA_RUN_GATED_SMOKES=1 qa/outside-in/alice-desktop/runners/run-scenario.sh run alice-desktop-save-menu-dialog-write-proof'
```

The target scenario uses no `automation.timeoutSeconds` and no shell `timeout` wrapper. Bounded waits live in the Java proof and surface as named `status: "blocked"` artifacts instead of hanging.

## 2. Find the artifact

Open the generated artifact:

```text
core/ide/target/save-menu-proofs/robot-save-menu-dialog-write-readback-proof.json
```

The artifact must be fresh for the current run and must match the scenario and run ID that the runner passed to Maven.

## 3. Trace run identity

Start with the top-level identity fields:

```json
{
  "schemaVersion": "eatme.alice-desktop-save-menu-dialog-write-readback-proof/v1",
  "scenario": "alice-desktop-save-menu-dialog-write-proof",
  "workflow": "save-menu-dialog-write-proof",
  "runId": "save-proof-20260509T001341Z",
  "status": "proven"
}
```

If `status` is not `proven`, the scenario fails closed. Read `blocker.kind` for the executable blocker and do not cite the artifact as Save completion proof.

## 4. Trace the Save path steps

Review the `menu`, `dialog`, `control`, `write`, and `readback` objects:

```json
{
  "menu": {
    "fileMenuOpened": true,
    "saveMenuItemInvoked": true,
    "saveActionIdentityMatched": true
  },
  "dialog": {
    "saveDialogObserved": true,
    "dialogShowing": true
  },
  "control": {
    "selectedPathSet": true,
    "approvedSelection": true
  },
  "write": {
    "fileWritten": true
  },
  "readback": {
    "projectReadable": true,
    "markerPresent": true
  }
}
```

Every required flag must be `true` for a proven artifact. These fields show that the same rendered run started from Robot File-menu activation, reached the production Save dialog, controlled the chooser, wrote the file, read it back, and found the marker.

## 5. Trace dialog control

Review `dialog`:

```json
{
  "dialog": {
    "dialogType": "Swing JFileChooser",
    "dialogClass": "javax.swing.JDialog",
    "saveDialogObserved": true,
    "dialogShowing": true,
    "ambiguousChooserDiscovery": false
  }
}
```

`approvedSelection: true` means the proof verified and approved the selected target through the live chooser. `ambiguousChooserDiscovery: true` blocks proof because the runner cannot safely attribute control to one dialog.

## 6. Trace write and readback

Review `control`, `write`, and `readback` together:

```json
{
  "control": {
    "normalizedSelectedPath": "projects/robot-save-menu-proof.a3p",
    "expectedPath": "projects/robot-save-menu-proof.a3p",
    "selectedPathMatchesExpected": true,
    "targetInsideProofRoot": true
  },
  "write": {
    "outputPath": "projects/robot-save-menu-proof.a3p",
    "fileWritten": true,
    "outputSizeBytes": 2379
  },
  "readback": {
    "projectReadable": true,
    "marker": "robotSaveMenuRoundTripMarker",
    "markerPresent": true
  }
}
```

The runner validates that the output path resolves under the proof root, the file exists, `write.outputSizeBytes` matches the filesystem size, the file reads back, and the marker is present.

## 7. Check boundaries

Finish by reading `doesNotClaim`. A correct proven artifact still excludes Save behavior outside this one path:

```json
{
  "doesNotClaim": [
    "Save As coverage",
    "overwrite prompt coverage",
    "cancellation coverage",
    "retry coverage",
    "native file dialog coverage",
    "all Save variants",
    "lesson completion",
    "grading correctness",
    "broad desktop automation"
  ]
}
```

Use the artifact only for the rendered File -> Save menu/dialog/control/write/readback/marker path. Keep broader Save claims for separate proofs.
