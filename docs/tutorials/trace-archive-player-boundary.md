# Tutorial: Trace the Archive/Player Boundary

This tutorial walks through the finished JSON player archive boundary from a
supported `.a3w` read, to the legacy image-resource compatibility path, to the
nearby fail-closed unsupported cases.

## Goal

Protect this behavior:

```text
A JSON .a3w player archive must decode its manifest-declared program type,
return only the narrow legacy image-resource compatibility project when that
exact shape applies, or fail closed with IOException. Resource-only readback is
not a full player-program decode.
```

## 1. Start with a supported program

Use a manifest whose `description.name` matches the Tweedle type:

```text
description.name = ProgramWithField
metadata.fileType = a3w
```

Use a small supported source:

```java
class ProgramWithField {
  WholeNumber count;
}
```

Read through the production API:

```java
Project project = IoUtilities.readProject(playerArchiveFile);
```

The expected result is a decoded program type:

```java
assertNotNull(project.getProgramType());
assertEquals("ProgramWithField", project.getProgramType().getName());
```

If the same archive contains a valid image reference and image entry, the image
also reads back as a project resource.

## 2. Trace the legacy image-resource compatibility case

The compatibility case is intentionally specific. The manifest names `Program`,
declares exactly one `Program` Tweedle type, and declares exactly one image
resource:

```text
version.txt
manifest.json
src/Program.twe
resources/picture.png
```

The `Program` source reaches an unsupported decode boundary, such as a resource
expression shape generated by player export. The image entry is present and
readable.

For that exact shape, the reader returns a resource-only project:

```java
Project project = IoUtilities.readProject(playerArchiveFile);

assertNull(project.getProgramType());
Resource resource = project.getResources().iterator().next();
assertEquals(ImageResource.class, resource.getClass());
```

The `null` program type is part of the contract. It prevents this path from being
mistaken for a complete, editable, or executable player decode.

## 3. Move one step outside the compatibility shape

Change one thing at a time and the archive fails closed.

For an unsupported program without safe image recovery:

```java
class Program extends MissingSuper {}
```

The public read boundary throws:

```java
IOException thrown = assertThrows(IOException.class,
    () -> IoUtilities.readProject(playerArchiveFile));
```

Assert bounded message fragments:

```java
assertTrue(thrown.getMessage().contains("Unsupported legacy JSON project archive"));
assertTrue(thrown.getMessage().contains("Program Tweedle decode is unsupported"));
assertTrue(thrown.getMessage().contains("no safe legacy resource recovery applies"));
```

## 4. Check the unsupported neighbors

The following changes all keep the archive outside the safe compatibility shape:

| Change | Why it fails closed |
| --- | --- |
| Replace the image with an audio resource | Audio is not part of legacy image recovery. |
| Add a model reference beside the image | Extra unsupported resource references block partial recovery. |
| Omit the image data entry | The image cannot be safely recovered. |
| Add a sibling Tweedle type reference | Multiple type references block partial recovery. |

For the missing-image case, the top-level message stays bounded and the missing
archive entry is available from the cause:

```java
assertNotNull(thrown.getCause());
assertTrue(thrown.getCause().getMessage().contains(imageReference.file));
```

## 5. Keep the evidence narrow

This trace proves an archive/player boundary only:

- supported manifest-declared program readback;
- exact legacy image-resource compatibility readback;
- fail-closed neighboring unsupported shapes;
- scenario, gated-command, workflow, and silver-thread contract readiness when
  the contract scripts pass.

It does not prove full UI automation, rendered-scene correctness, learner-world
grading, rubric scoring, or broad Tweedle language support.
